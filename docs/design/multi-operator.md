# 対象を東京都内の鉄道に広げる 設計書

- 状態: ドラフト（2026-10-09）
- 対象: `backend/assets`・`scripts/update_assets.sh`、`internal/client`、`internal/service`、`internal/route`（乗り換え・直通運転）、フロントの路線一覧、`infra`（Lambda のメモリ・SSM・CD）
- 関連: [経路探索エンジン 設計書](route-search.md)、[AI 鉄道エージェント 設計書](ai-api.md)

---

## 1. 目的

都営交通だけを扱っているアプリを、東京都内（島しょ部を除く）の鉄道の乗り換え・遅延情報アプリに広げる。

- 運行情報・列車位置・駅時刻表・遅れを反映した経路検索・AI チャットを、都内を走る他社の路線にも広げる。
- 都内の駅どうしなら、事業者をまたいだ経路を検索できるようにする。

---

## 2. 対応範囲

### 2.1 地域

- 東京都の23区・市町村（島しょ部を除く）にある駅を対象にする。駅が都内にあるかは、駅の座標（`geo:lat` / `geo:long`）を区市町村の境界と照らし合わせて決める（5章）。
- 都外の駅は、出発駅・到着駅に指定できない。ただし、列車が都外を通って都内に戻る区間（横浜線の町田付近、京王相模原線の若葉台付近など）は、経路がつながるように残す（5.2）。
- 直通運転の列車の行先は、都外の駅でも名前を表示する（今の `through_service.go` の辞書と同じ役目）。

都内に駅を持つ事業者のうち、ODPT にデータがあるもの。ライセンスで2つに分かれる（10章）。

| 東京メトロ | 基本 | 10 | ○ | **無し**（2026-10-09 の昼に取得して0件） | ○ |

## 3. データ

### 3.1 取得元

| ホスト | キー | 対象 |
|---|---|---|
| `api-public.odpt.org` | 不要 | 都営（今と同じ） |
| `api.odpt.org` | `ODPT_CONSUMER_KEY` | 基本ライセンスの事業者 |
| `api-challenge.odpt.org` | `ODPT_CHALLENGE_CONSUMER_KEY` | チャレンジ限定ライセンスの事業者 |

- 駅・路線・列車種別・運行情報・列車位置は、事業者ごとの API（`/api/v4/odpt:<型>?odpt:operator=...`）で取る。いずれも 1,000 件未満なので切れない。
- **列車時刻表・駅時刻表は、事業者ごとの API だと 1,000 件で切れる**（メトロ・JR・京王・東武の列車時刻表、JR の駅時刻表）。各ホストの全件ダウンロード用の URL（`/api/v4/odpt:TrainTimetable.json`・`odpt:StationTimetable.json`）で取る。2026-10-09 に取得し、全件そろっていることを確かめた。
  - `api.odpt.org` の全件版は、列車時刻表 64MB・駅時刻表 81MB（都営を含む）
  - `api-challenge.odpt.org` の全件版は、列車時刻表 91MB・駅時刻表 136MB

### 3.2 量（都内に絞ったあと）

| | 都営だけ（今） | 都内（5.2 の絞り方） | 倍率 |
|---|---|---|---|
| 列車時刻表の停車 | 12.2万 | 53.8万 | 4.4倍 |
| 駅時刻表の発車 | 11.7万 | 63.5万 | 5.4倍 |
| 軽量化した列車時刻表（gob） | 1.8MB | 8.7MB | |
| 軽量化した駅時刻表（gob） | 2.3MB | 14.0MB | |

都内に絞らないと、列車時刻表 81万、駅時刻表 99万になる（都外の JR の路線が大半）。

### 3.3 データの癖（今の `assets/slim` で変換できないもの）

都内に絞ったデータを今の `cmd/gen-assets` にかけると、次の2つでエラーになった。

| 癖 | 件数 | 扱い |
|---|---|---|
| 行先が2駅以上ある（分割・併合する列車） | 駅時刻表: JR 53・小田急 8、列車時刻表: JR 15 | 行先を複数持てるようにする |
| 時刻の無い停車（`departureTime` も `arrivalTime` も無い） | JR 508・京王 94・メトロ 44 | 経路探索では、その駅で乗り降りできないものとして飛ばす。始発駅に時刻が無い列車（例: 日比谷線 A845T の北千住）もある |

ほかに、次の違いがある。

- ダイヤ種別: 京王に `odpt.Calendar:Specific.Keio.SaturdayHolidayOnRaceDay`（競馬開催日の土休日）がある。開催日はデータに無いので、通常の土休日ダイヤを使い、この種別は使わない（駅時刻表の画面では「競馬開催日」として出し分ける）。
- 駅時刻表の列車ID（`odpt:train`）: 列車時刻表の無い5社は、駅時刻表にも列車ID・列車番号が無い。都営の「列車をクリックすると位置を出す」機能は、これらの社では使えない。
- 運行情報: 京急・西武は会社全体で1件（`odpt:railway` が null）。JR の運行情報（`jre-is`）は JR東日本の全域（東北・新潟なども）なので、対象の路線に絞る。JR だけ `odpt:trainInformationStatus`（「遅延」など）が入っている。
- 路線の色: JR は 88 路線のうち 41 路線にしか `odpt:color` が無いが、都内の路線にはすべてある。TX には色が無いので、フロントで補う。

## 4. データの置き場所と更新

### 4.1 リポジトリに置かない

基本ライセンスとチャレンジ限定ライセンスは、どちらも第8条4項で、データとその**派生データ（元のデータの全部または大部分を復元できるもの）を、第三者が再利用できる状態で公開・再配布すること**を禁じている。このリポジトリは公開しているので、他社のデータは JSON も gob もコミットしない。

- 都営のデータ（CC BY 4.0）は、今までどおりリポジトリに置く。テストはこれと、テスト用の小さな架空のデータで行う。
- 他社のデータは、手元では gitignore したディレクトリ（`backend/assets/extra/`）に置く。本番用には、非公開の S3（Lambda アーティファクト用のバケット）に取得日ごとに置く。
- `go:embed` は、ファイルが無いとビルドできない。`assets/extra/` にはコミットするファイル（README）を1つ置き、gob が無ければ都営だけで動くようにする。CI の検証（PR）は gob 無しで動く。

### 4.2 取得と生成

```
scripts/update_assets.sh            （手元。backend/.env のキーを使う。キーは表示しない）
  └ 都営: 今と同じ → assets/*.json（コミットする）
  └ 他社: 全件版を取得 → 都内に絞る → assets/extra/*.gob（コミットしない）
                                     → S3 に取得日ごとにアップロード
deploy.yml（CD）
  └ S3 から assets/extra/*.gob を取得 → ビルド → 埋め込む
```

- 都内に絞る処理（駅の座標と区市町村の境界の照合）は `cmd/gen-assets` に持たせる。境界のデータ（国土数値情報の行政区域。都内53区市町村）は変わらないので、絞った結果の駅の一覧（駅ID）をリポジトリに置き、取得のたびには照合しない。駅の一覧は駅IDだけなので、ODPT のデータの再配布にはあたらない。
- ライセンスの第4条2項(4)は、データが更新されたら成果物を直ちに更新することを求めている。ダイヤ改正のときの手動の更新に加えて、取り直しを定期的に（週1回など）行う仕組みを、段階4以降で作る（13章）。

### 4.3 キー

| 使う場所 | 置き場所 |
|---|---|
| 手元（取得・開発） | `backend/.env`（gitignore 済み）。`ODPT_CONSUMER_KEY`・`ODPT_CHALLENGE_CONSUMER_KEY` |
| 本番の Lambda（運行情報・列車位置） | SSM Parameter Store の SecureString: `/train-status-app/dev/odpt-consumer-key`・`/train-status-app/dev/odpt-challenge-consumer-key` |

- Gemini のキーと同じく、Terraform・tfvars・Lambda の環境変数・ログ・レスポンスにキーを出さない。リクエストの URL にキーが入るので、ODPT の取得に失敗したときのログやエラーに URL をそのまま出さない（今の `client` はエラーに URL を含めていないが、テストで確かめる）。
- Lambda は、他社のリアルタイムの情報を初めて取るときに SSM から読み、プロセスが続く間は持ち続ける（AI のキーと同じ）。SSM を読めないあいだは、都営だけを返す。
- SSM を読む権限は、`infra/bootstrap` にポリシーを作り、deploy 用ロールの `LambdaExecutionRolePolicy` の条件にその ARN を足す（CLAUDE.md の手順）。

## 5. 都内への絞り込み

### 5.1 駅

- 駅の座標が、都内53区市町村の境界の中にある駅を対象にする。座標の無い駅（JR の新幹線・東北の駅など 72 駅）は対象外になるが、都内の在来線の駅にはすべて座標がある。
- 判定の結果（2026-10-09）: 都内の駅は 889 駅、駅名にまとめると 626。23区内だけなら駅名は 466。

### 5.2 列車時刻表

- 列車ごとに、都内の最初の停車から最後の停車までを残す。途中で都外を通る停車も残す（増えるのは約3,500停車、1%未満）。都内に停車が1つしかない列車は捨てる。
- 都外の停車は、経路の途中で通るだけにし、出発駅・到着駅・乗り換え駅にはしない。

### 5.3 駅時刻表

- 都内の駅の駅時刻表だけを残す。

## 6. 乗り換え

### 6.1 乗り換えられる駅

他社の駅データには、乗り換え先の駅（`odpt:connectingStation`）が入っている（都営の `station.json` には無い）。これを乗り換えの対応表のもとにする。

- 都内の駅で、同じ名前の駅の組は 546 組あり、そのうち 538 組が `odpt:connectingStation` に入っている。名前の違う乗り換え駅は 123 組（東京 ⇔ 大手町、浜松町 ⇔ 大門、春日 ⇔ 後楽園など）。都営どうしの組（東日本橋 ⇔ 馬喰横山）は入っていない。
- 都営の駅にはこの項目が無いので、他社の駅から都営の駅への乗り換えを逆向きにも足す（乗り換えは両方向とする）。都営どうしの乗り換えは、今の「同じ名前の駅」と `differentNameTransfers` を残す。
- 同じ名前でも離れている駅がある（早稲田: 東西線 ⇔ 荒川線 733m、浅草: TX ⇔ 都営・メトロ 600〜680m）。同じ名前の駅を出発駅・到着駅として1つにまとめる今の扱いは、600m 以内の駅に限る。

### 6.2 乗り換えにかかる時間

- 今は一律5分。他社に広げると、通路の長い駅（東京 ⇔ 大手町 404m、新宿 ⇔ 新宿西口 約500m など）が増えるので、駅の座標の直線距離から決める。
- 案: `3分 + 距離 ÷ 80m/分`（切り上げ）。直線距離は実際の通路より短いので、係数は代表的な駅（東京・新宿・大手町・春日・蔵前）の乗り換え案内の時間と比べて決める。
- 同じ駅・同じ路線の乗り継ぎ（1分）は今のまま。

## 7. 直通運転

### 7.1 データの形

列車時刻表は、事業者ごとに自社の区間しか持っていない。直通運転の列車（例: 新宿線 → 京王線、半蔵門線 → 東急田園都市線・東武スカイツリーライン）は、境目の駅で別々の列車として載っている。`odpt:nextTrainTimetable` / `previousTrainTimetable` は事業者をまたいでいない（2026-10-09 に確認。事業者の中で路線が変わるときだけ使われている）。

このままだと、経路検索で直通の列車に乗り続けても、境目の駅（押上・渋谷・中目黒・目黒・新宿・和光市など）で「乗り換え」になり、乗り換え時間が足されて到着が遅くなる。

### 7.2 境目でつなぐ

境目の駅で、次の条件をすべて満たす2本の列車を、1本の列車としてつなぐ。

- 片方の終点と、もう片方の始発駅が、同じ駅か `odpt:connectingStation` でつながる駅である
- 同じダイヤ種別である
- 片方の終点の到着時刻と、もう片方の始発駅の発車時刻の差が 0〜5分
- 列車番号が同じ（会社によって末尾の記号が違うので、数字の部分で比べる。比べ方は実装のときにデータで確かめる）

つないだ列車は経路探索の中だけで使う（列車の詳細の画面は、今と同じく事業者ごとの列車IDで出す）。つなげなかった列車の数を生成のログに出し、境目の駅ごとの割合を見て条件を直す。

## 8. 列車時刻表の無い事業者（東急・西武・小田急・京急・ゆりかもめ）

都内の駅名の約4分の1（626 のうち 159。三軒茶屋・自由が丘・二子玉川・羽田空港・お台場・田無・東村山など）は、この5社の駅しかない。経路検索に入れないと、これらの駅は出発駅・到着駅にできない。

### 8.1 駅時刻表から列車の運行を推定する

駅時刻表は、駅・方向・ダイヤ種別ごとの発車時刻の一覧で、各発車に列車種別と行先がある（列車ID は無い）。これを、隣の駅の発車へ順につないで列車を作る。

- 同じ路線・方向・ダイヤ種別・列車種別・行先の発車を、駅の並び（`odpt:stationOrder`）の順に、次の駅の発車のうち、時刻が後で最も近いものへつなぐ。
- 種別ごとに分けるので、急行が各停を追い越しても入れ替わらない。同じ種別どうしは追い越さない前提にする。
- 終点の到着時刻は駅時刻表に無いので、1つ前の駅の発車時刻に、その区間のほかの列車から求めた所要時間を足す。

### 8.2 正しさの確かめ方

都営には駅時刻表と列車時刻表の両方がある。都営の駅時刻表に同じ推定をかけ、本物の列車時刻表と比べて、正しくつながった列車の割合を測る。メトロ・JR でも同じように測れる。十分な割合（目安 95% 以上）になってから、5社に使う。

推定した列車は、経路検索の結果に「推定」と分かるようにはしない（駅時刻表の発車時刻はそのまま正しいので）。到着時刻の誤差（終点の推定など）は、測った結果を見て判断する。

## 9. リアルタイムの情報

### 9.1 取得

| 情報 | 対象 | 取得 |
|---|---|---|
| 運行情報（`odpt:TrainInformation`） | 全事業者 | 3ホストに事業者ごとに問い合わせる（11件）。並列に取り、30秒キャッシュする（今と同じ） |
| 列車位置（`odpt:Train`） | 都営・JR・京王・東武・京急 | 同上 |

メトロ・TWR・TX・多摩モノレールの GTFS-RT は運行情報（Alert）だけで、遅れ（TripUpdate）・位置（VehiclePosition）は無い（2026-10-09 に確認）。列車時刻表の無い5社には GTFS も無い。

- 1つの事業者の取得に失敗しても、ほかの事業者の結果は返す。失敗した事業者は「取得できませんでした」と出す。今の `ErrExternalAPI`（都営の取得に失敗したら全体がエラー）は、全事業者が失敗したときだけにする。
- チャレンジ限定の事業者は、設定（11章）で無効にしたら問い合わせない。

### 9.2 遅れの反映（経路検索）

- 列車位置に遅れがある事業者（都営・JR・京王・東武）は、今と同じく路線・方向ごとの遅れの中央値を使う。
- それ以外（メトロなど）は、運行情報の文章で「見合わせ」を判定する今の仕組みだけを使う。文章は事業者ごとに言い回しが違うので、事業者ごとの例で判定のテストを足す。
- 京急・西武のように会社全体で1件の運行情報は、その会社の全路線に当てはめる。

## 10. ライセンス

### 10.1 公共交通オープンデータ基本ライセンス（メトロ・TWR・TX・多摩モノレール・ゆりかもめ）

- 営利・非営利を問わず、成果物を一般に公開して使える。期限は無い。
- 派生データの公開・再配布の禁止（4.1）、データが更新されたら直ちに成果物を更新すること、センター・提供者が保証していると受け取られる表示をしないこと。

### 10.2 公共交通オープンデータチャレンジ限定ライセンス（JR・京王・東武・京急・東急・西武・小田急）

- **公共交通オープンデータチャレンジへの作品の応募が前提**（第4条1項）。応募以外の目的があると主催者が判断すると、利用を止められ、法的措置もありうる。
- **許諾は 2027年3月12日に終わり、終わったらただちに利用をやめる**（第13条）。チャレンジ専用のアクセストークンも「チャレンジ期間中のみ」使える。
- 応募期間は 2026年10月1日〜2027年1月11日 23:59（JST）。提出するもの: 誰でも使える作品の URL、説明（400字程度）、紹介資料（PDF）、紹介動画（YouTube、3分以内）、スクリーンショット（5枚以内）、使ったオープンデータの一覧、アンケート（チャレンジ後も公開を続けるか、など）。
- 応募規約（`https://developer.odpt.org/challengeterms`）は、ログインしないと開けなかった（2026-10-09）。応募の前に読む。
- 派生データの公開・再配布の禁止は基本ライセンスと同じ。
- 正確性・完全性について責任を負わないことを一般ユーザに知らせ、問い合わせ先を書く（第10条3項）。

チャレンジに応募することにした（2026-10-09）。チャレンジ限定の事業者は、次のようにして入れる。

## 11. 実行環境

### 11.1 メモリと起動

都内に絞ったデータで gob を作り、今の main と同じコードで起動して測った（手元の x86、2026-10-09）。

| | 今（都営だけ） | 都内 |
|---|---|---|
| 起動してから応答できるまで | 52ms | 172ms |
| 起動直後のメモリ（RSS） | 63MB | 173〜182MB |
| 経路検索を1回したあとのメモリ | 74〜77MB | 206〜231MB |
| 実行ファイル（arm64） | 38MB | 57MB |

本番の Lambda では、今は Max Memory Used が約95MB（手元より約18MB多い）。都内にすると約250MB の見込みで、今の 256MB では足りない。

- **Lambda のメモリを 512MB にする**。以前 512MB を試したのはコールドスタートを縮めるためで、効果が無かったので戻した。今回は、データが入りきらないので上げる。
- コールドスタート（今の Init Duration は約240ms）は、手元の差（+120ms）から 400ms 前後と見込む。デプロイしたら REPORT のログで確かめる。
- 他社の駅・路線・列車種別の JSON（合わせて約2MB）も、駅時刻表と同じく使う項目だけにして埋め込む。

### 11.2 RAPTOR の索引

- 経路探索の索引は、ダイヤ種別の組み合わせごとに初めて検索するときに作る（今と同じ）。都内では列車が約4倍になるので、索引を作る時間（初回の検索の遅さ）を測り、遅ければ起動時に平日の分だけ先に作る。

## 12. 画面・AI への影響

- **路線の一覧**: 75 路線になるので、事業者ごとにまとめて折りたたむ。今のホームの路線のアコーディオンを、事業者 → 路線の2段にする。路線の色・記号は今と同じく `GET /api/routes` から引く。
- **駅の選択**: 同じ名前の駅が事業者をまたいで増える（新宿は都営・メトロ・JR・京王・小田急）。駅を選ぶ画面では、駅名でまとめたあとに事業者・路線を選ぶ。
- **列車位置**: 列車位置の無い事業者（メトロなど）では、時刻表の列車をクリックしても位置を出さない（今の日暮里・舎人ライナーと同じ扱い。`trainLocationUnsupported`）。
- **AI**: 道具の説明の例（`odpt.Railway:Toei.Mita` など）と、`internal/station` の駅名の特定は、事業者をまたいだ同じ名前の駅に対応させる。評価セット（`eval.yaml`）に、他社の駅・事業者をまたぐ経路の例を足す。
- **アプリの説明**: 「都営の」を「東京都内の」に変える（`index.html`・README・Swagger の `@description`）。
- **運賃**: 他社をまたぐ乗り継ぎの割引が ODPT に無いので、運賃の検索は都営のままにする（運賃の機能をやめるかは別に決める）。
